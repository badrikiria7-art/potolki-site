# AGENTS.md

## Назначение проекта

Одностраничный сайт услуг по натяжным потолкам в Краснодаре и Краснодарском крае. Сайт служит портфолио и базой доверия для посетителей, включая переходы из Avito.

## Технологический стек

- React 19, JavaScript/JSX.
- Vite 8 beta.
- Tailwind CSS 4 через `@tailwindcss/vite`.
- `lucide-react`.
- ESLint 9.
- npm и `package-lock.json`.
- Одна страница с якорными секциями, без роутера.
- Vercel deployment; serverless functions находятся в `api/`.

## Структура

- `src/main.jsx` — точка входа React.
- `src/App.jsx` — страница, контент, портфолио и клиентская часть формы.
- `api/telegram.js` — server-side отправка заявок в Telegram.
- `src/index.css` — Tailwind и глобальные стили.
- `public/works/` — фотографии портфолио.
- `index.html` — HTML-шаблон и базовые метаданные.
- `vite.config.js` — React, Vite и Tailwind.
- `eslint.config.js` — lint.
- `dist/` — локальный результат сборки, исключённый из Git.

## Порядок работы

1. До изменений проверить `git status`, существующую реализацию и затрагиваемые файлы.
2. Не перезаписывать пользовательские изменения и не выполнять destructive-команды.
3. Вносить минимальные локальные изменения без переписывания проекта и смены визуального стиля.
4. Не обновлять зависимости и lock-файл без необходимости и согласования.
5. Не создавать commit, push или deploy без прямой просьбы пользователя.
6. После изменений запускать `npm run build` и `npm run lint`.
7. Проверять desktop и mobile; при изменениях breakpoint также tablet.
8. Не считать локальную проверку подтверждением работы production или внешней интеграции.

## Telegram и секреты

- React отправляет форму только через `POST /api/telegram`.
- Telegram Bot API вызывается только из `api/telegram.js`.
- Используются server-side переменные `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID`.
- Никогда не переносить эти значения в `VITE_*`, клиентский код, логи или отчёты.
- Реальные значения не записывать в `.env.example` или другие файлы проекта.
- Локальные `.env` и `.env.*` должны оставаться исключёнными из Git; `.env.example` хранит только пустые имена переменных.
- Не отправлять тестовую заявку реальному получателю без отдельного разрешения.
- При изменении формы проверять валидацию, sending/success/error, повторную отправку, тайм-аут и недоступность интеграции.

## Изображения и портфолио

- Не удалять, не перезаписывать, не ухудшать и не заменять оригиналы без явного согласования.
- Различать реальные объекты, процесс монтажа, технические фотографии и 3D-визуализации.
- Не выдавать визуализации за реальные работы; при публикации маркировать `Визуализация проекта`.
- Не называть фотографию выполненной работой компании без подтверждения владельца.
- Для публичных изображений задавать точный русский `alt` и подходящую стратегию загрузки.
- Перед массовой обработкой делать dry-run, карту изменений и сохранять возможность отката.

## Цены и бизнес-факты

- Не менять цены и офферы автоматически.
- `310 ₽/м²` — цена полотна, а не потолка под ключ.
- Подтверждённый контекст: монтаж от `600 ₽/м²`, монтаж с материалом от `700 ₽/м²`.
- Оффер Avito: `Натяжные потолки под ключ`, `от 700 ₽/м²`, `Бесплатный замер`.
- Любая цена должна однозначно описывать состав предложения.
- Не выдумывать отзывы, гарантии, статистику, сроки, скидки, партнёров и выполненные работы.

## Контакты, SEO и аналитика

- Не менять телефон, email, WhatsApp, Telegram, социальные ссылки и получателя заявок без подтверждения владельца.
- Сохранять русскую локализацию и географию: Краснодар и Краснодарский край.
- При SEO-изменениях согласованно проверять title, description, H1/H2/H3, canonical, Open Graph, robots, sitemap и alt.
- Не подключать аналитику и внешние сервисы без отдельного согласования.

## Визуальный стиль и UX

- Сохранять тёмный стиль, cyan/violet градиенты, карточную композицию и одностраничную структуру.
- Не менять тексты, секции, CTA, цены, формы и контакты вне согласованной задачи.
- Проверять overflow, читаемость, меню, touch targets, focus-состояния, якоря и отсутствие битых изображений.
